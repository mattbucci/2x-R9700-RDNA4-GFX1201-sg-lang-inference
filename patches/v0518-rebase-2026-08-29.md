# SGLang v0.5.18 rebase validation

## Target

- SGLang tag: `v0.5.18` (peeled commit `71de97b264b04dcd514cf904003028aefe9775c8`, tagged 2026-08-20)
- Serving tree: `/data/sgl-v0518`  ·  Conda environment: `sglang-triton36-v0518`
- PyTorch `2.11.0+rocm7.2` · Triton `3.6.0` · transformers `5.12.1` (unchanged) · ROCm 7.2.3
- Previous base: v0.5.16 (`fdebc938`). v0.5.17 was skipped; the delta v0.5.16→v0.5.18 is 4513 files,
  +405k/−100k lines.

## Upstream changes that shaped this rebase

- **Kernel tree relocation.** `sgl-kernel/` is gone from the monorepo (removed in v0.5.17). Its source now
  lives at `python/sglang/kernels/aot/` (the `sglang-kernel` 0.4.6.post1 package source, still with
  `setup_rocm.py`). Patches 003/006/008/032 are re-pathed there; `scripts/setup.sh` and the three native
  builders resolve the kernel dir version-aware (`default_sgl_kernel_dir` in `scripts/common.sh`).
- **`sglang.jit_kernel` is gone.** JIT/Triton modules moved under `python/sglang/kernels/ops/...`
  (`moe_fused_gate` → `kernels/ops/moe/`, `triton_store_cache` → `kernels/ops/kvcache/`,
  `minimax_m3/rmsnorm` → `kernels/ops/layernorm/minimax_m3_rmsnorm.py`). `test/registered/jit/` →
  `test/registered/kernels/`. Patches 065/081/082/097 and their tests are re-pathed; 065's
  `tree_verify_attention.py` now lives at `kernels/ops/attention/` next to the kernels it imports.
- **Packaging split.** `python/pyproject.toml` is now the CUDA build (pins `torch==2.13.0`, flashinfer
  cu13, sgl-deep-*, nvidia-*, tilelang, …); `python/pyproject_other.toml` carries the platform-neutral
  `runtime_common` extra used by upstream's ROCm image. `setup.sh` installs the package with `--no-deps`
  and resolves `runtime_common` from `pyproject_other.toml`, adds the ROCm-side extras the CUDA file
  carried (`numba`, `zstandard`, `watchfiles`, `torchcodec==0.11.1` for the torch-2.11 ABI), and installs
  the `sglang-kernel==0.4.6.post1` wheel as the package skeleton for the HIP `common_ops` overlay. The
  `srt_hip` extra's `petit_kernel`/`wave-lang` (MI300 FP4 / wave attention) are deliberately not installed.
- **OCI image.** `Dockerfile` pins `v0.5.18` / `71de97b2`; `docker/build-sglang.sh`'s TP=1 store-cache
  fallback tweak now targets `python/sglang/kernels/ops/kvcache/kvcache.py` (signature-tolerant anchor,
  `can_use_store_cache(k_row_bytes, v_row_bytes=0)`); the sampler guard target is unchanged. Not rebuilt
  as part of this rebase.
- **Runtime context.** `get_server_args()` reads inside layers became `get_exec().comm.*` /
  `get_spec().*`; `ModelRunner.dcp_size` no longer exists (`server_args.dcp_size`); the scheduler's
  `get_internal_state` reads `get_context().resolved_server_args_dict()`.
- **`SGLANG_OPT_USE_JIT_KERNEL_FUSED_TOPK` was removed**; the unified Triton router is unconditional
  on CUDA. Upstream also added a guarded `download_remote_media` (SSRF policy) for HTTP media, a
  `mambaish_config` union for hybrid v-head-dim detection, `ModelConfig.get_max_num_attention_heads()`,
  `is_lm_only`, and a reworked MoE tuner (`enable_up_tma`, three tuning rounds).

## Series transition: 69 → 70

Independent dry-run of the v0.5.16 series on pristine v0.5.18: **37 applied clean, 32 required work.**
Sequential rebase result: **43 unchanged, 26 regenerated** (2 pure re-paths, 8 fuzz-only, 16 hand-rebased).
No patch was dropped; **1 patch added** — `098-gemma4-unified-native-config`: sglang's
`_Gemma4UnifiedConfigAlias` (a `Gemma4Config` subclass registered for `model_type=gemma4_unified`) shadows
transformers 5.12.1's native `Gemma4UnifiedConfig`, so the encoder-free 12B got the SigLIP
`Gemma4VisionConfig` and died at init on `model_patch_size`. This is the v0.5.16-era "config-alias boot
crash" the 3090 team reported; it was masked on this rig because patch 072's vendored config carried the
attribute until v0.5.16 dropped 072, and gemma4-12b was not in the v0.5.16 validation set (its 5/5 baseline
is from v0.5.15). 098 prefers the native class and keeps the alias only for older transformers.

### Hunk-level upstreaming (dropped during rebase; patch retained)

- `077`: the max-query-head sizing (`_max_num_attention_heads` + both `num_head` call sites) is upstream
  as `ModelConfig.get_max_num_attention_heads()`; the helper and its unit test were removed. The FP8
  descale-from-KV-dtype fix and the ROCm FP8 saturating store remain.
- `092`: upstream now validates the required/named JSON array (non-list / missing-name raise); 092 keeps
  the empty-array guard and the full `finish_reason` dict restore.
- `096`: upstream's `download_remote_media` (redirect/limit policy) replaced the raw `session.get` in

  `SGLANG_ALLOW_REMOTE_MEDIA` / `SGLANG_ALLOW_LOCAL_MEDIA` gates are layered over it. The three
  `server_args` sensitive-field markers and all seven `STRICT_PATCHES` markers are intact.

### Hand-rebased (semantic re-anchoring)

- `001`: `is_causal_lm_only` composed with upstream's new `is_lm_only` (`language_model_only` config flag
  — not equivalent, no local checkpoint sets it); the HIP FP32 attention all-reduce replaces upstream's
  `get_exec().comm.enable_quant_communications` block. Fuzz-placed Gemma4/triton_backend hunks verified
  (decode KV-shared block sits in `forward_decode`; extend is upstream).
- `008`: upstream added `gfx1250` to the accepted targets and to the large-LDS branch; RDNA4 detection is
  now `startswith("gfx12") and != "gfx1250"` so gfx1250 keeps upstream behaviour.
- `027`: import hunk re-anchored (upstream added `get_device_core_count`, `is_gfx95_supported`).
- `032`: `environ.py` grew a 30-line preamble; `patch --fuzz=3` had dropped the `Envs` hunk *outside* the
  class. Placed by hand before the "Model configuration" banner inside `class Envs`.
- `047`: re-anchored on the new `elif mambaish_config(...)` branch; `mamba2_config` is still an
  isinstance list, so the duck-typed `get_v_head_dim` guard for the remote-code Nano-Omni config stays.
- `057`: `is_per_image` moved from `managers/mm_utils.py` to `managers/mm_schedule.py`; still required
  (upstream's condition is still offset-only).
- `065`: split-KV tree verify is still gfx95-only upstream (`use_verify_splitkv`), so the opt-in gfx1201
  path stays; kernel relocated to `kernels/ops/attention/tree_verify_attention.py`, `merge_state` import
  updated.
- `075`: the tuner was refactored upstream (up/down TMA rounds). Rebased: `per_channel_quant` threaded
  through all six positional `benchmark_config` call sites, both TMA kernel constructions honour it,
  TMA variants are skipped on HIP (`_is_hip`), HIP configs carry no `USE_TMA` key, `RuntimeError` is
  caught alongside `OutOfResources` in all three tuning loops, and the single-batch path saves both
  configs.
- `079`: with the env gate removed upstream, the HIP enablement is `elif _is_cuda or (_is_hip and
  get_bool_env_var("SGLANG_OPT_USE_JIT_KERNEL_FUSED_TOPK", "true"))` so 076's torch fallback stays
  reachable for A/B runs (HIP-only; CUDA follows upstream). Its unit tests now toggle that env var via
  `patch.dict(os.environ, …)` instead of patching `envs.…get`, and the fused-router test mocks
  `sglang.kernels.ops.moe.moe_fused_gate`. A first regeneration of 079 had silently lost the
  `cohere2_moe.py`/`laguna.py`/test hunks (tree reset during the 077 amend); caught by a per-patch
  file/hunk audit against the originals and rebuilt from a worktree at the 078 state.
- `080`: `hip_fp32_allreduce` appended after upstream's new `enable_fused_ar_quant` /
  `fused_ar_quant_keep_bf16` params; the else-branch uses `get_exec().comm.enable_quant_communications`.
- `081`: `_use_triton_hip_rmsnorm` placed after `_flashinfer_rmsnorm_quant_available`; Laguna imports
  re-anchored on `get_exec` runtime context; kernel + test re-pathed.
- `082`: kernel hunk re-pathed to `kernels/ops/kvcache/triton_store_cache.py`; imports updated. The fused
  FP8 store gate used `self.same_kv_dim`, which v0.5.18 removed from `MHATokenToKVPool` (upstream now
  passes K/V row widths separately); it is now `self.head_dim == self.v_head_dim`. Found by the fleet
  run: every FP8-KV preset (first seen on glm45-air) crashed in `set_kv_buffer` at the first prefill.
- `088`: `server_args.dcp_size` replaces the removed `ModelRunner.dcp_size`; test import re-anchored.
- `096`: see above; `grpc_bridge.get_server_info` now reads `self.tokenizer_manager.server_args`.

- `026`: extended to `get_video_feature`. v0.5.18 delivers the validator's 12-frame video to the Gemma4
  tower (the v0.5.16 baseline never did — its video probe answered "please provide the video"), and the
  batched tower call materializes the position one-hot for all frames (~1.15 GiB), which OOMed
  gemma4-31b at CTX=131072/MEM=0.92 (760 MiB free). The per-frame loop 026 already used for images is
  now applied to video as well. Side effect: 026 is no longer the non-unique-anchor double-apply
  exception — the series now rejects 69/69 on a second application.
